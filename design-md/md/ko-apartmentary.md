# 아파트멘터리 웹 디자인 시스템

> 근거: 관찰 기반 (모바일 웹 캡처: 아파트멘터리 웹사이트를 휴대폰 브라우저로 본 홈 화면 5장(첫 화면, 서비스 소개, 시공 사례 2장, 후기), 약 453px 폭 이미지에서 픽셀 측정. 원래 기기 폭은 확인 필요, 이미지 1px ≈ CSS 1px로 봄. 실측일 2026-10-31)
> 작성: SylviaLab · 최종 수정 2026-10-31

이 문서는 디자인 시스템의 다섯 층(원칙, 토큰, 컴포넌트, 사용 규칙, 구현·검증)을 한 파일로 줄인 요약이다. 맨 위 YAML은 도구와 AI가 그대로 읽는 값이고, 아래 글은 그 값을 언제·왜 쓰는지 설명한다.

## 1. 개요와 원칙
- 서비스 성격: 아파트 인테리어 리모델링 회사의 웹사이트. 서비스 소개, 평형·유형별 시공 사례, 고객 후기, 쇼룸 소식을 보여준다.
- 디자인 인상 한 줄: 흰 바탕에 진한 회색 글자, 거의 검정인 알약 버튼 하나. 시공 사진을 크게 깔고 색은 사진에 맡긴다.
- 공식 시스템 이름: 공개된 이름 없음
- 디자인 원칙(공식 원칙은 찾지 못했다)
  1. 색은 사진에 맡긴다. UI 색은 흰색, 검정, 회색뿐이고 따로 정한 강조색은 보이지 않았다. (관찰에서 정리)
  2. 사진은 각지게, 누르는 것은 둥글게. 사진 모서리 0px, 버튼·번호 알약 999px, 중간 모서리 값은 없다. (관찰에서 정리)
  3. 행동은 하나로 모은다. 묶음마다 거의 검정(#13130b) 알약 버튼 하나를 콘텐츠 왼쪽 선에 맞춘다. (관찰에서 정리)
  4. 그림자 없이 여백과 1px 선으로만 나눈다. (관찰에서 정리)
- 톤: 차분한 흑백, 잡지처럼 사진이 먼저.

### 이 문서를 읽는 AI 에이전트에게
- UI 색은 YAML의 흑백 일곱 값 밖으로 나가지 않는다. 강조색이 필요해 보여도 새로 만들지 않는다. 색은 사진 몫이다.
- 행동 버튼은 `button-primary`(#13130b 알약) 하나를 묶음 끝 왼쪽에 둔다. 순수 검정 #000000은 공지 띠·진행 막대·아이콘 몫이다.
- 모서리는 `rounded.none`(사진) 아니면 `rounded.full`(누르는 것) 둘 중 하나만 고른다.
- 크기 값은 453px 폭 캡처 추정(±10%)이다. 비율과 순서를 지키는 것이 숫자를 지키는 것보다 중요하다.
- 판단이 어려우면 요소를 빼고 사진과 여백을 남긴다.

### 특장점
- UI가 완전한 흑백이다 — 바탕 #ffffff, 글자 #212121·#4d4d4d·#666666, 버튼 #13130b, 공지 띠·진행 막대 #000000, 선 #e2e2e2가 전부다. 이 모음의 다른 커머스 앱(예: 오늘의집의 하늘색, 올리브영의 코럴 빨강)과 달리 강조색이 없다.
- 버튼 검정에 노란 기운을 섞었다 — 주요 알약 버튼은 순수 검정이 아니라 #13130b이고, 공지 띠·진행 막대만 #000000이다.
- 사례 넘김을 진행 막대로 보여 준다 — 점 대신 폭 전체 1px #e2e2e2 선 위에 2~3px 검정 막대를 두고 막대 길이로 위치를 알린다.
- 머리를 사진 위에 투명하게 얹는다 — 맨 위 29px 검정 공지 띠 아래, 첫 사진 위에 검정 "A" 심볼과 햄버거 메뉴만 올리고 바탕 띠를 두지 않는다.
- 시공 사례 묶음이 정해진 세로 리듬을 따른다 — 두 줄 제목 → 22px → 3:2 꽉 찬 사진 → 20px → 이름 → 12px → 한 줄 설명 → 16px → 평당 가격 → 약 40px → 진행 표시 → 22px → 버튼.

### 배울 점
- 사진이 상품인 서비스를 만들 때 아파트멘터리처럼 UI 색을 흑백으로 비우고 사진 모서리를 0으로 두어 사진이 화면을 이끌게 한다.
- 가로로 넘기는 묶음을 만들 때 아파트멘터리처럼 점 대신 1px 선 위 진행 막대로 위치와 남은 양을 함께 보여 준다.
- 묶음마다 행동이 하나일 때 아파트멘터리처럼 왼쪽 정렬 어두운 알약 버튼("○○ 더 보기 >") 하나로 끝맺는다.

## 2. 색상
값은 캡처 이미지 픽셀에서 읽었다. UI 요소(바탕·글자·버튼·선) 색만 적었고 시공 사진 속 색은 넣지 않았다. 작은 글자 색은 번짐 때문에 오차가 있다. 토큰 이름은 SylviaLab이 붙인 것이다.

### 색 체계
단계 팔레트(primitive)는 없다. 화면 전체가 흑백 일곱 값이라 "관찰 색 → 역할 이름" 한 층으로 정리했다.

| 관찰 색 | HEX | 역할 이름 |
|---|---|---|
| 흰색 | #ffffff | background, text-on-dark |
| 옅은 회색 | #e2e2e2 | progress-track |
| 중간 회색 | #666666 | text-tertiary |
| 진한 회색 | #4d4d4d | text-secondary |
| 거의 검정 | #212121 | text-primary |
| 노란 기운 검정 | #13130b | action-fill |
| 순수 검정 | #000000 | notice-fill, progress-bar, icon |

### 브랜드·행동
| 토큰 | HEX | 쓰임 |
|---|---|---|
| button-dark | #13130b | 주요 알약 버튼 바탕("○○ 더 보기 >") |
| black | #000000 | 맨 위 공지 띠 바탕, 슬라이드 진행 막대, 로고·메뉴 아이콘 |

### 바탕·선
| 토큰 | HEX | 쓰임 |
|---|---|---|
| white | #ffffff | 기본 바탕 |
| line | #e2e2e2 | 슬라이드 진행 표시의 바탕 선(1px) |

### 글자
| 토큰 | HEX | 쓰임 |
|---|---|---|
| text-primary | #212121 | 구획 제목, 사례 이름, 가격 줄, 후기 문장, 번호(01·02) |
| text-secondary | #4d4d4d | 소개 문단, 사례 한 줄 설명(작은 글자라 ±오차) |
| text-tertiary | #666666 | 후기 작성자 줄(작은 글자라 ±오차, 근사값) |
| text-on-dark | #ffffff | 알약 버튼 글자, 공지 띠 글자 |

### 상태
- 상태 색(오류·성공), 링크 색: 확인 필요
- 사진 위 슬라이드 번호 알약("3 / 8 >")은 반투명 어두운 바탕이라 HEX를 정할 수 없다. 확인 필요.

### 역할별 색
- **#13130b**: 주요 알약 버튼 바탕 하나. 흰 굵은 글자를 얹는다. hover·눌림 짝은 확인 필요.
- **#000000**: 맨 위 공지 띠, 슬라이드 진행 막대, 로고 심볼·메뉴 아이콘.
- **글자 세 단계**: 제목·이름·가격·후기 #212121 → 소개 문단·사례 설명 #4d4d4d → 작성자 #666666.
- **선 하나**: 진행 표시 바탕 1px #e2e2e2. 구획을 나누는 선은 없다.
- **상태 색·링크 색**: 확인 필요.

### 화면 모드
- 밝은 화면만 관찰했다. 다크 모드는 확인 필요.

### 색 사용 규칙
- UI에는 흰색, 검정, 회색만 쓴다. 색은 시공 사진에 맡긴다.
- 주요 버튼 바탕은 #13130b, 공지 띠와 진행 막대는 #000000.
- 제목·이름·가격·후기 문장은 #212121, 설명 문단은 #4d4d4d, 작성자처럼 가장 작은 정보는 #666666.
- 선은 슬라이드 진행 바탕 1px #e2e2e2 하나만 보였다.

### Don't
- 빨강·파랑 같은 강조색을 UI에 넣지 않는다.
- 버튼 바탕을 #000000으로 두지 않는다. #13130b다.
- 본문 글자를 #000000으로 쓰지 않는다. #212121이다.
- 구획 사이에 #e2e2e2 선을 긋지 않는다. 이 선은 진행 표시 전용이다.

## 3. 타이포그래피
- 글꼴: 한글 산세리프(추정. Pretendard·Noto Sans KR과 비슷한 모양. 실제 이름 확인 필요)
- 대체 글꼴: 확인 필요
- 로고 워드마크: 둥근 기하학 모양의 영문 소문자 산세리프("Apartmentary"). 머리에는 "A" 모양 심볼만 쓴다.
- 크기는 한글 글자 높이 ÷ 0.9, 숫자 높이 ÷ 0.7로 계산한 추정값이다(±1). 글꼴에 따라 실제는 1~2 클 수 있다. 이미지 1px을 1pt로 적었다.

### 위계와 사용처
| 단계 | 크기(pt) | 굵기 | 행간 | 쓰임 |
|---|---|---|---|---|
| section-title | 19 | 700 | 약 27px(1.4) | 두 줄 구획 제목 |
| card-title | 12 | 700 | 확인 필요 | 시공 사례 이름 |
| review | 11 | 700 | 약 18px | 후기 문장 |
| button | 11 | 700 | 확인 필요 | 알약 버튼 글자 |
| body | 11 | 400 | 약 17px(1.5) | 소개 문단 |
| notice | 11 | 400 | 확인 필요 | 맨 위 공지 띠 |
| price | 10 | 700 | 확인 필요 | 평당 가격 줄 |
| caption | 10 | 400 | 확인 필요 | 사례 한 줄 설명, 후기 작성자, 번호 |

### 글자 사용 규칙
- 구획 제목은 19px/700 두 줄로 끊는다(행간 1.4).
- 굵기는 400과 700 두 가지만 보였다. 이름·가격·후기 문장·버튼은 700, 설명·작성자는 400.
- 제목(19px)과 나머지 글자(10~12px)의 크기 차이를 크게 둔다.

### Don't
- 400·700 밖의 굵기를 쓰지 않는다.
- 구획 제목을 한 줄로 길게 늘이지 않는다. 두 줄로 끊는다.
- 제목과 본문 사이 크기를 좁히지 않는다(19px ↔ 10~12px).
- 사례 설명 끝에 마침표를 찍지 않는다.

- 간격 단계(관찰, pt): 8, 12, 16, 20, 24, 40

### 간격 적용 규칙
- 시공 사례 묶음 세로 순서: 두 줄 제목 → 22px → 사진(폭 꽉 참, 약 3:2) → 20px → 사례 이름 → 12px → 한 줄 설명 → 16px → 가격 → 약 40px → 진행 표시 → 22px → 알약 버튼.
- 서비스 소개 묶음: 사진을 좁게(폭 약 210px, 왼쪽 약 40px 들여) 놓고, 아래 제목·문단·버튼을 같은 선에 맞춘다.
- 후기 목록: 번호(01, 02) 열 + 문장 열, 문장 시작은 왼쪽 약 58px. 후기 사이 약 78px.
- 버튼은 왼쪽 정렬로 콘텐츠 선에 맞춘다.

### Don't
- 버튼을 가운데·오른쪽에 두지 않는다. 콘텐츠 왼쪽 선에 맞춘다.
- 사례 묶음의 세로 순서(제목 → 사진 → 이름 → 설명 → 가격 → 진행 → 버튼)를 바꾸지 않는다.
- 사진 좌우에 여백 테를 두르지 않는다. 시공 사진은 폭 꽉 채움이다(소개 사진만 좁게 들여 놓는다).
- 묶음을 카드 상자로 감싸지 않는다.

## 5. 모서리·고도·모션
| 토큰 | 값 | 쓰임 |
|---|---|---|
| radius-none | 0px | 시공 사진, 첫 화면 사진, 공지 띠 |
| radius-full | 999px | 주요 알약 버튼, 사진 위 슬라이드 번호 알약 |

- 테두리: 1px #e2e2e2(슬라이드 진행 표시 바탕 선).
- 사진은 각지게, 누르는 것은 완전히 둥글게. 중간 모서리 값은 캡처에서 보이지 않았다.
### 고도
- 고도(그림자·층): 그림자는 보이지 않았다. 층은 사진 위에 투명 머리를 얹는 것 하나다.
- 이미지 1px을 CSS 1px로 보고 적었다.
### 모션
- 모션(길이·이징): 캡처로 알 수 없음. 확인 필요. 진행 막대가 슬라이드와 함께 움직이는지도 확인 필요.

### Don't
- 4~16px 같은 중간 모서리 값을 만들지 않는다. 0 또는 999px.
- 그림자를 넣지 않는다.
- 버튼을 각지게 만들지 않는다.

## 6. 컴포넌트
컴포넌트마다 변형, 상태, 쓰는 때, 쓰지 않는 때를 적는다. 보지 못한 상태는 `확인 필요`.

### 6.1 버튼

**크기**

| 크기 | 높이 | 폭 | 모서리 | 글자 |
|---|---|---|---|---|
| 기본(유일) | 약 38px | 글자에 맞춤(약 116~143px) | 999px | 11px/700 |

**종류**

| 변형 | 모양 | 쓰는 때 |
|---|---|---|
| 주요 알약 버튼 | #13130b 바탕, 높이 약 38px, 폭은 글자에 맞춤(약 116~143px), 999px. 흰 굵은 글자 + 오른쪽 `>` | 묶음 끝에서 더 보기·서비스 알아보기 |
| 외곽선·보조 버튼 | 확인 필요 | 확인 필요 |

- 상태: 눌림·비활성·로딩 모두 확인 필요.

**규칙** (관찰에서 정리)
- 한 묶음에 버튼은 하나(묶음마다 하나만 보였다).
- 콘텐츠 왼쪽 선에 맞추고 묶음 맨 끝에 둔다.
- 문구는 "○○ 더 보기 >" / "서비스 알아보기 >" 꼴, 끝에 `>`.
- 38px 높이는 44pt보다 낮다. 실제 기기 배율 확인 뒤 터치 영역을 44pt 이상으로 넓힌다. (구현 권장)

### 6.2 입력창
- 캡처에 없음. 확인 필요.

### 6.3 칩·탭
- 캡처에 없음. 확인 필요.

### 6.4 카드·리스트
- 시공 사례: 두 줄 제목 + 꽉 찬 사진(모서리 0, 약 3:2) + 이름(굵게) + 한 줄 설명(회색) + 평당 가격(굵게). 가로로 넘기는 묶음으로 보인다.
- 슬라이드 진행 표시: 폭 전체 1px #e2e2e2 선 위에 2~3px 두께 검정 막대. 막대 길이로 현재 위치를 보여준다.
- 후기: 왼쪽 두 자리 번호, 오른쪽 굵은 후기 문장(두 줄까지), 아래 회색 작성자 줄. 작성자는 가린 이름을 쓴다.
- 상태: 사례 넘김 중 모양, 사진 눌림은 확인 필요.

**규칙** (관찰에서 정리)
- 진행 표시는 점이 아니라 1px 선 + 검정 막대로, 막대 길이로 위치를 보여 준다.
- 진행 표시에는 "8개 중 3번째" 같은 글자 정보를 함께 준다(`aria-valuenow` 등). (구현 권장)
- 사진에는 시공 공간을 설명하는 대체 텍스트를 단다. (구현 권장)

### 6.5 상단 바·하단 탭 바
- 맨 위 공지 띠: 검정 바탕 높이 약 29px, 가운데 흰 작은 글자(11px), 오른쪽 흰 X 닫기.
- 머리: 첫 사진 위에 투명하게 얹는다. 왼쪽 검정 "A" 심볼, 오른쪽 검정 햄버거 메뉴 아이콘.
- 첫 화면 사진 왼쪽 아래 반투명 알약에 "현재 / 전체 >" 슬라이드 번호.
- 하단 탭 바: 없음.
- 메뉴를 연 화면: 확인 필요.

### 6.6 바텀시트·모달
- 캡처에 없음. 확인 필요.

### 6.7 토스트·배지
- 캡처에 없음. 확인 필요.

### 6.8 아이콘·이미지
- 아이콘: 가는 선 아이콘(햄버거, X, `>`). 수가 적다.
- 사진: 화면 대부분. 밝은 톤 시공 완료 사진. 소개 사진 위에 흰 워드마크를 얹기도 한다.

## 7. 패턴
- 홈 구성: 공지 띠 → 사진 위 투명 머리 + 첫 화면 사진 슬라이드(번호 알약) → 서비스 소개(좁은 사진 + 제목 + 문단 + 버튼) → 시공 사례 가로 묶음(진행 막대 + 버튼) → 후기 번호 목록.
- 사례 넘기기: 가로 슬라이드 + 1px 선 위 진행 막대 + 아래 "○○ 더 보기 >" 버튼.
- 가격 보여 주기: 사례마다 "평당 ○○~○○만 원대" 범위를 굵게 한 줄.
- 목록 → 상세: 확인 필요(사례 상세를 보지 않았다).
- 검색: 확인 필요.
- 빈 상태·오류: 확인 필요.
- 폼(상담 신청): 확인 필요.

### 빈 상태·로딩·오류
- 홈 한 페이지만 봐서 빈 상태·로딩·오류 화면은 관찰하지 못했다. 확인 필요.
- 상담 신청 폼의 오류 문구가 필요하면 9장 말투(합니다체)를 따른다. 예:
  ```
  연락받을 휴대폰 번호를 입력해 주십시오
  ```
  (예시 문구, SylviaLab 작성)

## 8. 접근성
- 글자 대비(WCAG 2.x, 계산값):

| 글자 | 바탕 | 대비 | 본문 기준 4.5:1 |
|---|---|---|---|
| #212121 | #ffffff | 16.1:1 | 통과 |
| #4d4d4d | #ffffff | 8.5:1 | 통과 |
| #666666 | #ffffff | 5.7:1 | 통과 |
| #ffffff | #13130b | 18.7:1 | 통과 |
| #ffffff | #000000 | 21.0:1 | 통과 |
| #000000 | #e2e2e2 | 16.2:1 | 통과(진행 막대 / 바탕 선, 글자 아님) |
| #e2e2e2 | #ffffff | 1.3:1 | 미달(진행 바탕 선, 글자 아님) |

- 흑백만 써서 글자 대비는 모두 기준을 넘는다. 진행 표시 바탕 선(#e2e2e2, 흰 바탕과 1.3:1)은 글자가 아니지만 아주 옅다. 위치는 검정 막대로 읽는다.
- 터치 영역: 주요 알약 버튼 높이 약 38px, 공지 띠 약 29px. 둘 다 44pt보다 낮다(원래 기기 배율이 확인 필요라 실제 크기는 다를 수 있다).
- 최소 글자 크기: 10px(가격 줄, 사례 설명, 후기 작성자, 번호). 원래 배율에 따라 1~2 클 수 있다.
- 포커스·스크린리더·글자 확대: 확인 필요.

### 점검 목록
- 키보드·포커스: 캡처라 확인 필요. 슬라이드를 키보드로 넘길 수 있는지 확인 필요.
- 대체 텍스트: 사진 대부분이 정보다. 공간 설명 대체 텍스트를 권한다. (구현 권장)
- 공지 띠 닫기(X) 버튼과 햄버거 메뉴에 이름표를 단다. (구현 권장)
- 글자 확대: 10~11px 작은 글자가 많다. 200% 확대 동작은 확인 필요.
- 터치 영역: 버튼 약 38px, 공지 띠 약 29px로 44pt보다 낮다(배율 확인 필요).
- 색만으로 뜻 전달: 흑백만 쓰므로 색 의존은 없다. 진행 위치는 막대 길이로만 보인다.

## 9. 글쓰기 톤
- 말투: 소개 문단은 합니다체, 두 줄 정도. 후기는 해요체 고객 문장 + 가린 이름.
- 구획 제목: 꾸미는 말 + 명사로 끝나는 두 줄("○○한 / ○○ 아파트" 꼴).
- 사례 설명: 마침표 없는 한 줄, "~을 소개합니다" 꼴.
- 버튼 문구 꼴: "○○ 더 보기 >", "서비스 알아보기 >" 꼴.
- 숫자·단위 표기: 가격은 "평당 ○○~○○만 원대"처럼 범위로 적는다. 후기 번호는 두 자리(01, 02).

## 10. Do & Don't
관찰 기반 문서의 규칙은 "이 서비스 화면에서 반복되는 규칙"을 SylviaLab이 정리한 것이다(공식 규칙 아님).

### Do
- UI 색은 #ffffff, #212121, #4d4d4d, #666666, #13130b, #000000, #e2e2e2 안에서 쓴다.
- 주요 버튼은 #13130b 알약(999px), 높이 약 38px, 흰 굵은 글자 + `>`로 왼쪽 정렬한다.
- 시공 사진은 폭을 꽉 채운 3:2, 모서리 0px로 쓴다.
- 구획 제목은 19px/700 두 줄, 행간 1.4로 쓴다.
- 가로 묶음 아래에 1px #e2e2e2 선 + 2~3px 검정 진행 막대를 둔다.
- 사례 정보는 이름(12px/700) → 한 줄 설명(10px #4d4d4d) → 평당 가격(10px/700) 순서로 쌓는다.

### Don't
- 강조색(빨강·파랑 등)을 UI에 새로 넣지 않는다.
- 사진에 둥근 모서리를 주지 않는다. 4~16px 같은 중간 모서리 값을 쓰지 않는다.
- 카드·버튼에 그림자를 넣지 않는다.
- 머리에 바탕 띠를 깔지 않는다. 첫 사진 위에 투명하게 얹는다.
- 한 묶음에 버튼을 여러 개 두지 않는다.

## 13. 참고 자료
- 아파트멘터리 모바일 웹 화면 캡처 5장 (SylviaLab 벤치마킹 피그마 파일, 저장소에는 올리지 않음)
- 공개 URL: 이번 작업 환경에서 사이트 접속이 막혀 직접 확인하지 못했다. 확인 필요.

근거와 한계
- 캡처 시기는 확인 필요. 5장 모두 홈 한 페이지를 위에서 아래로 나눠 찍은 화면이다.
- 이미지 폭이 약 453px이라 원래 기기 폭과 배율을 알 수 없다. 크기·간격은 이미지 1px을 CSS 1px로 본 추정이라 ±10% 정도 차이가 날 수 있다.
- 일부 캡처 왼쪽 끝의 옅은 회색 그림자는 화면 전환 중 겹친 것으로 보고 UI 색에서 뺐다.
- 사례 상세, 상담 신청(입력창), 메뉴를 연 화면, PC 화면은 보지 못했다.
- 후기 작성자 이름, 단지 이름 같은 화면 속 정보와 문장은 옮기지 않았다.
- 관찰 값은 서비스가 바뀌면 달라질 수 있다.
- 8장 대비값과 "(관찰에서 정리)" 규칙은 SylviaLab이 이 문서의 HEX와 관찰 사실로 계산·정리한 것이다. 1장 비교는 같은 저장소의 오늘의집·올리브영 파일에 있는 사실이다.

서비스 이름과 브랜드는 각 권리자의 것이다. 이 문서는 식별·학습용 참고 자료로 SylviaLab이 독자적으로 작성했다.
