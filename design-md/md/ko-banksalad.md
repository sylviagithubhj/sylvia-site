# 뱅크샐러드 디자인 시스템

> 근거: 관찰 기반 (실측일 2026-10-31, WebFetch로 banksalad.com 홈 텍스트·메타 정보와 App Store 페이지 확인. 이 작업 환경은 브라우저·Playwright로 사이트를 열 수 없어 computed style은 재지 못함) + App Store 스크린샷 6장 픽셀 측정(관찰 기반, 2026-11-01 확인, 추정 포함)
> 작성: SylviaLab · 최종 수정 2026-11-01

이 문서는 디자인 시스템의 다섯 층(원칙, 토큰, 컴포넌트, 사용 규칙, 구현·검증)을 한 파일로 줄인 요약이다. 맨 위 YAML은 도구와 AI가 그대로 읽는 값이고, 아래 글은 그 값을 언제·왜 쓰는지 설명한다. 색·크기 값은 모두 App Store 홍보 스크린샷(작은 JPEG)에서 읽은 `추정`이다. 기기 캡처로 다시 재기 전에는 참고용으로만 쓴다.

## 1. 개요와 원칙
- 서비스 성격: 금융 마이데이터 앱. 자산·가계부 관리, 카드·대출·예적금·보험 비교, 무료 건강 검사까지 한 앱에서 다룬다. 주 무대는 앱이고 웹(banksalad.com)은 상품 비교·소개 중심.
- 디자인 인상 한 줄: 연회색(#f6f7f9) 바탕에 흰 카드를 쌓고, 녹색(#05a96c) 하나로 주요 버튼과 "늘어난·아낀 돈"을 표시하는 금융·건강 비교 화면(색은 스크린샷 추정).
- 공식 시스템 이름: 공개된 이름 없음(확인 필요)
- 디자인 원칙 (공식 원칙은 공개되지 않았다)
  1. 자산 섹션마다 최근 변동 금액을 오른쪽에 두어 "얼마나 바뀌었나"를 먼저 보여 준다. (관찰에서 정리, 기술 블로그 홈 탭 개편 글 기준)
  2. 홍보 문장은 해요체, 공식 고지는 합니다체로 어조를 나눈다. (관찰에서 정리)
  3. 행동 버튼은 "[대상] + 하기/바로가기/보기"로 끝을 맞춘다. (관찰에서 정리)
  4. 신뢰 고지 문장을 섹션 제목으로 올린다(제휴로 정확한 정보를 전한다는 내용). (관찰에서 정리)
  5. 접근성은 UI를 텍스트 스냅숏으로 바꿔 테스트한다(섹션 제목에 header 역할, 접히는 영역에 expanded 상태). (관찰에서 정리, 기술 블로그 접근성 글 기준)
- 톤: 혜택은 친근하게, 고지는 정중하게.
- 공개 자료 상황
  - 회사 기술 블로그(blog.banksalad.com)에 홈 탭 개편, 접근성, 게임 기획 글이 있으나 색·글꼴·간격 수치는 없다.
  - 홈 탭 개편 글에서 확인한 구성: 계좌·주식·카드·대출 섹션 오른쪽에 최근 변동 금액, 배너 영역, 인기 금융 상품, 퀵메뉴.
  - GitHub(banksalad) 공개 저장소에 디자인 토큰·컴포넌트 저장소는 없다. Figma 컴포넌트 목록 플러그인은 있다.

### 특장점
- 접근성을 자동 검사 도구로 다룬다 — UI를 텍스트 스냅숏으로 바꿔 비교하는 자체 도구 AXSnapshot을 GitHub에 공개했고, 섹션 제목 header 역할·접히는 영역 expanded 상태를 검사 예로 든다.
- 변동을 먼저 보여 주는 홈 — 앱 홈은 계좌·주식·카드·대출 섹션마다 오른쪽에 최근 변동 금액을 두고, 그 아래 배너·인기 금융 상품(카테고리별)·퀵메뉴를 잇는다.
- 어조로 홍보와 고지를 가른다 — App Store 기능 소개와 혜택 안내는 해요체(`받아요`, `찾아보세요`), FAQ·대출·권한 고지는 합니다체다. 목록 기호도 기능 소제목 `●`, 세부 항목 `·`, 고지 `■`로 나눈다.
- 금융과 건강을 한 메뉴에 둔다 — 웹 상단 메뉴 7개(카드, 대출, 예적금, 무료 건강 검사, 건강 보험, 자동차보험, 머니피드)에 금융 비교와 건강 검사가 나란히 있다.
- 지출을 빨갛게 칠하지 않는다 — 가계부 목록에서 지출(−10,000원 꼴)은 검정, 수입(+)만 녹색, 결제 취소는 연회색(#b5b6ba 근처)으로 흐리게 둔다. 돈을 쓴 것을 경고처럼 보이지 않게 한다. (관찰에서 정리, App Store 스크린샷 추정)
- 화면 위쪽에 "결과 숫자 한 개"를 크게 둔다 — 순자산·월 보험료·지출/수입처럼 화면마다 맨 위에 굵은 큰 금액 하나, 그 위에 회색 작은 이름표를 둔다. 세부는 아래 흰 카드로 내린다. (관찰에서 정리, App Store 스크린샷 추정)

### 배울 점
- 자산·잔액 목록을 만들 때 뱅크샐러드처럼 섹션 오른쪽에 최근 변동 금액을 붙여 바뀐 것을 먼저 보게 한다.
- 홍보와 법적 고지가 한 화면에 섞일 때 어조(해요체 / 합니다체)와 목록 기호(`●` / `■`)로 둘을 나눈다.
- 접근성을 검사할 때 화면을 텍스트 스냅숏으로 바꿔 header 역할·expanded 상태가 빠지지 않았는지 비교한다.
- 가계부·거래 내역을 만들 때 뱅크샐러드처럼 지출은 기본 글자색, 수입만 강조색으로 칠해 화면이 경고색으로 뒤덮이지 않게 한다. (관찰에서 정리)
- 여러 혜택을 한 번에 받게 할 때 카드 묶음 맨 아래에 폭 꽉 찬 녹색 버튼 하나만 둔다. 개별 카드는 ">" 이동만 준다. (관찰에서 정리)

### 이 문서를 읽는 AI 에이전트에게
- 이 문서의 색·간격·모서리 값은 App Store 홍보 스크린샷에서 읽은 `추정`이다. YAML에 있는 값만 쓰고, 없는 값(글꼴 이름, 글자 크기 pt, 다크 모드)은 지어내지 않는다.
- 쓸 수 있는 것은 구성과 말투다: 자산 섹션 오른쪽 변동 금액, 해요체(혜택)·합니다체(고지) 나누기, "[대상] + 하기/바로가기/보기" 버튼 라벨.
- 접히는 영역에는 expanded 상태, 섹션 제목에는 header 역할을 붙인다. 이것은 회사가 접근성 글에서 든 예다.
- 판단이 어려우면 더 정중한 쪽(고지 어조)과 더 단순한 구성을 고른다.

## 2. 색상
### 색 체계
- 공개 팔레트는 없다. App Store 스크린샷 6장(2026-11-01 수집)에서 픽셀을 뽑아 "관찰 팔레트 → 역할" 두 층으로 적었다. 모두 `추정`이다.
- 측정 방법: 넓은 면(버튼·카드·바탕)은 가장 많이 나온 색, 글자는 가장 진한(또는 채도가 높은) 픽셀을 골랐다. 이미지가 221×480px JPEG라 작은 글자 색은 번져서 실제보다 연하게 읽힌다.
- 홍보 이미지의 바깥 바탕(#293038 남색, #e8ecef 회색)은 앱 화면이 아니라 뺐다.
- 이 서비스에서 꼭 필요한 역할은 일반 앱보다 하나 많다: 변동 금액 증가(`amount-up`)와 감소(`amount-down`).
- 웹 홈 메타 정보에는 theme-color가 없다.

## 10. Do & Don't
관찰 기반 문서의 규칙은 "이 서비스 화면에서 반복되는 규칙"을 SylviaLab이 정리한 것이다(공식 규칙 아님). 색·크기 값은 App Store 스크린샷에서 읽은 `추정`이다.

### Do
- 자산 섹션(계좌·주식·카드·대출)마다 오른쪽에 최근 변동 금액을 둔다.
- 행동 버튼 라벨은 "~하기", "~바로가기", "~보기"로 끝낸다.
- 혜택 안내는 해요체, FAQ·대출·권한 고지는 합니다체로 쓴다.
- 앱 설명 목록은 기능 소제목 `●`, 세부 항목 `·`, 고지 `■`로 구분한다.
- 섹션 제목에는 header 역할, 접히는 영역에는 expanded 상태를 붙인다.
- 앱 내려받기 버튼은 구글플레이·앱스토어 두 개를 나란히 둔다.
- 화면 바탕은 연회색(#f6f7f9), 내용은 흰 카드(모서리 약 10pt)에 담는다. (추정)
- 주요 버튼은 녹색(#05a96c) 바탕 + 흰 굵은 글자, 폭 꽉 차게 하나만 둔다. (추정)
- 수입·절약 금액만 녹색, 지출은 검정으로 쓴다. (추정)

### Don't
- 고지 문장(대출·권한)을 해요체 홍보 어조로 쓰지 않는다.
- 웹 상단 메뉴 7개와 사이드 메뉴 항목을 서로 다르게 두지 않는다(같은 메뉴를 반복한다).
- 버튼 라벨을 "확인"처럼 대상 없이 쓰지 않는다. "[대상] + 하기" 꼴로 대상을 넣는다.
- 지출 금액을 빨강으로 칠하지 않는다.
- 한 카드 묶음에 녹색 주요 버튼을 둘 이상 두지 않는다.
