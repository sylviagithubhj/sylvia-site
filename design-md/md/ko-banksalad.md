# 뱅크샐러드 디자인 시스템

> 근거: 관찰 기반 (실측일 2026-10-31, WebFetch로 banksalad.com 홈 텍스트·메타 정보와 App Store 페이지 확인. 이 작업 환경은 브라우저·Playwright로 사이트를 열 수 없어 computed style은 재지 못함)
> 작성: SylviaLab · 최종 수정 2026-10-31

## 1. 개요
- 서비스 성격: 금융 마이데이터 앱. 자산·가계부 관리, 카드·대출·예적금·보험 비교, 무료 건강 검사까지 한 앱에서 다룬다. 주 무대는 앱이고 웹(banksalad.com)은 상품 비교·소개 중심.
- 디자인 인상 한 줄: 금융과 건강을 함께 묶은 비교·추천 화면. 색·크기 수치는 이번에 재지 못했다(아래 표 참고).
- 공식 시스템 이름: 공개된 이름 없음(확인 필요)
- 공개 자료 상황
  - 회사 기술 블로그(blog.banksalad.com)에 홈 탭 개편, 접근성, 게임 기획 글이 있으나 색·글꼴·간격 수치는 없다.
  - 홈 탭 개편 글에서 확인한 구성: 계좌·주식·카드·대출 섹션 오른쪽에 최근 변동 금액, 배너 영역, 인기 금융 상품, 퀵메뉴.
  - 접근성 글: UI를 텍스트 스냅숏으로 바꿔 접근성을 테스트하는 자체 도구 AXSnapshot을 소개한다(GitHub 공개). 섹션 제목에 header 역할, 접히는 영역에 expanded 상태를 붙이는 예를 든다.
  - GitHub(banksalad) 공개 저장소에 디자인 토큰·컴포넌트 저장소는 없다. Figma 컴포넌트 목록 플러그인은 있다.

## 6. 주요 컴포넌트
수치는 모두 확인 필요. 아래는 2026-10-31 웹 홈 텍스트 구조와 기술 블로그에서 확인한 구성이다.

### 버튼
- 홈의 행동 버튼은 "[대상] + 하기/바로가기/보기" 형태: 상품 바로가기, 서비스 사용해 보기, 더 알아보기, 최저금리 조회하기, 이벤트 보기.
- 앱 내려받기 버튼 두 개(구글플레이, 앱스토어)를 나란히 둔다.
- 크기·색·상태 값은 확인 필요.

### 입력창
- 확인 필요.

### 카드·리스트
- 웹 홈 섹션 순서: 대출 혜택 배너 → 서비스 소개 → 금융매칭 소개 → 카드 이벤트 → 데이터·매칭 강점 두 항목 → 추천 글(Pick) 목록 → 제휴 고지.
- 앱 홈(블로그 기준): 자산 섹션마다 최근 변동 금액을 오른쪽에 둔다. 배너, 인기 금융 상품(카테고리별), 퀵메뉴가 이어진다.
- 푸터는 "많이 찾는 서비스", "뱅크샐러드", "이용 안내" 세 묶음의 링크 목록.

### 상단 바·탭 바
- 웹 상단 메뉴 7개: 카드, 대출, 예적금, 무료 건강 검사, 건강 보험, 자동차보험, 머니피드. 같은 메뉴가 사이드 메뉴에도 반복된다.

## 8. 글쓰기 톤(UX 라이팅)
- 말투(관찰)

  - 혜택 안내는 해요체(`받아요`, `찾아보세요`).
  - App Store 기능 소개는 해요체, FAQ·대출·권한 고지는 합니다체. 홍보 문장과 공식 고지를 어조로 나눈다.
- 줄임말 `뱅샐`을 메뉴 이름에 그대로 쓴다(뱅샐머니).
- 신뢰 고지 문장을 섹션 제목으로 둔다(제휴로 정확한 정보를 전한다는 내용).
- 앱 설명의 목록 기호: 기능 소제목 `●`, 세부 항목 `·`, 고지 `■`.

근거와 한계
- 뱅크샐러드는 공개 디자인 시스템 문서나 코드가 없다.
- 이 작업 환경은 셸에서 banksalad.com에 접속할 수 없고, WebFetch는 페이지를 글자로만 바꿔 가져와 CSS 링크와 스타일이 빠진다. 그래서 색, 글꼴, 크기, 간격, 모서리 수치를 하나도 확인하지 못했다. 하위 페이지(/cards)는 본문이 비어 와서 홈 한 화면만 봤다.
- 다음 단계: 브라우저(Playwright 등)로 홈, 목록, 상세 세 화면의 computed style을 재서 2~6절을 채운다. 앱 전용 화면은 스토어 스크린샷으로 `추정` 표시.
- 관찰 값은 사이트가 바뀌면 달라질 수 있다.
- 서비스 이름과 브랜드는 (주)뱅크샐러드의 것이다. 이 문서는 식별·학습용 참고 자료로 SylviaLab이 독자적으로 작성했다.
