## 1. 개요와 원칙
- 서비스 성격: 패션·뷰티 온라인 편집숍. 브랜드 상품 목록, 랭킹, 세일, 발매 정보가 중심이다. 웹(musinsa.com)과 iOS·Android 앱.
- 디자인 인상 한 줄: 흰 바탕에 검정·회색 글자. 웹은 거의 검정(#1a1b1f) 상단 바를 쓰고, 앱 구매 흐름은 파랑(#0078ff) 큰 버튼 하나로 결제까지 끌고 간다. 할인은 빨강, 할인 금액은 하늘색 숫자로 보여 준다.
- 공식 시스템 이름: 공개된 이름 없음. 웹 CSS에서 공통 색 변수(:root)는 찾지 못했다.
- 디자인 원칙(공식 원칙은 공개되지 않음):
  1. 사진이 주인공이다. 상품 사진은 모서리 없이(0px) 꽉 채우고, 장식은 줄인다. (관찰에서 정리)
  2. 혜택은 숫자로 말한다. 할인율·할인 금액·구매자 수·판매량을 숫자로 앞에 둔다. (관찰에서 정리)
  3. 한 화면에 큰 행동 하나. 앱 구매 흐름은 화면 폭 파랑 버튼 하나로 결제까지 끌고 간다. (관찰에서 정리)
  4. 평평하게 나눈다. 그림자 대신 10pt 회색 띠와 1pt 선으로 구획을 나눈다. (관찰에서 정리)
  5. 모서리는 작게. 0~4px가 기본이고, 원형은 아이콘·체크·라디오·작은 알약 배지에만 쓴다. (관찰에서 정리)
- 톤: 사진과 숫자를 촘촘하게 보여 주는 쇼핑 화면. 색은 할인·쿠폰·결제에만 쓴다.

### 특장점
- 할인을 두 색으로 쪼갠다 — 할인율은 빨강("12% SAVE" #ff0000, 웹 #f31110), 할인 금액은 하늘색 #14aaff 숫자(-1,521원)라 "몇 %"와 "얼마"가 한눈에 갈린다.
- 구매 흐름 전체를 파랑 버튼 하나가 끌고 간다 — 옵션 시트 → 장바구니 → 주문서까지 화면 폭 351×48pt #0078ff 버튼이 하단에 고정되고, 문구는 "[금액] 결제하기"로 금액이 먼저 나온다.
- 그림자 대신 띠로 나눈다 — 앱은 10pt #f1f1f1 띠와 1pt 선만으로 구획을 나누고, 그림자는 시트·하단 고정 영역 위쪽에만 쓴다. 웹은 그림자가 없다.
- 사진을 모서리 0으로 꽉 채운다 — 웹 카드 사진 246×295px, 앱 썸네일 66×80pt 모두 0px이고 다른 요소도 0~4px라 상품 사진이 화면의 주인공이 된다.
- 숫자로 사회적 증거를 보여 준다 — 웹 랭킹 배지("[숫자]명이 구매 중", "판매 [숫자]개", 높이 16px)와 검색 순위 2열 목록(1~3위 파랑, 변동 삼각형, 기준 시각)이 고르는 이유를 숫자로 준다.

### 배울 점
- 할인 정보를 보여 줄 때 무신사처럼 할인율(빨강 %)과 할인 금액(다른 색 마이너스 숫자)을 다른 색으로 나눈다.
- 여러 단계 결제 흐름을 만들 때 무신사처럼 하단 고정 버튼 하나에 금액을 앞세운 문구("[금액] 결제하기")를 넣어 단계마다 같은 자리에서 다음으로 넘긴다.
- 정보가 많은 주문 화면을 나눌 때 무신사처럼 그림자 카드 대신 10pt 회색 띠와 1pt 선으로 구획을 나눈다.

### 관찰한 특징
- 웹 글꼴은 Pretendard 하나. 자간 기본값(normal).
- 앱 구매 흐름(옵션 → 장바구니 → 주문서)의 주요 버튼은 화면 폭 파랑 버튼(높이 48pt, 모서리 4pt)이다. 주문 완료 화면의 "다음" 버튼과 작은 "사용" 버튼은 검정이다.
- 그림자는 아래에서 올라오는 시트와 하단 고정 버튼 영역 위쪽의 옅은 그림자뿐이다.
- 앱 홈 상단(로고 줄·검색창·메인 탭)은 웹과 같은 거의 검정(#1a1b1f) 바탕이다. 그 아래 본문 바탕은 연회색(#f5f5f5)이고, 흰 칩·카드를 그 위에 올린다.
- 앱 하단 탭 바는 흰 바탕 5칸(카테고리·스냅·홈·좋아요·마이), 홈이 가운데다.
- 앱 검색 화면은 순위 숫자 1~3위만 파랑으로, 순위 변동은 빨강 위 삼각형·파랑 아래 삼각형으로 보여 준다.

### 이 문서를 읽는 AI 에이전트에게
- 색·크기는 YAML 토큰 이름(`primary-app`, `sale`, `discount-amount`, `section-band`)으로 쓴다. 관찰 팔레트(`gray-120` 등)보다 역할 이름을 먼저 쓴다.
- 웹 값(px, 본문 13px)과 앱 값(pt, 본문 14pt)을 섞지 않는다. 만드는 화면이 웹인지 앱인지 먼저 정한다.
- 파랑 #0078ff는 앱 구매 흐름의 행동·선택 표시에만, 빨강은 할인율에만, 하늘색 #14aaff는 할인 금액 숫자에만 쓴다.
- 상품 사진은 모서리 0, 나머지 요소는 0~4px. 판단이 어려우면 그림자 대신 #f1f1f1 띠, 모서리는 작게, 혜택은 숫자로 보여 주는 쪽을 고른다.
- 관찰 기반이라 값은 바뀔 수 있다. 확인 필요 항목(다크 모드, 토스트, 포커스)은 지어내지 말고 비워 둔다.

## 2. 색상
웹 값은 세 화면(홈 추천, 랭킹, 상품 상세)의 computed style에서 반복된 값이다. 괄호 안 숫자는 홈 화면에서 그 색을 쓴 글자 요소 수다. 앱 값은 1배율 캡처 픽셀에서 읽었다. 넓은 면 색은 정확하고, 작은 글자 색은 글자 테두리 번짐 때문에 오차가 있다. 토큰 이름은 SylviaLab이 붙인 것이다.

### 색 체계
무신사는 공개된 색 체계가 없다. 그래서 이 문서는 **관찰 팔레트 → 역할 이름** 두 층으로 정리했다(관찰에서 정리).

| 층 | 예시 | 쓰는 곳 |
|---|---|---|
| 관찰 팔레트 | `gray-120`, `blue-app`, `sky`, `red-web` | 화면에서 잰 값 그대로. YAML 정의에만 |
| 역할 이름 | `section-band`, `primary-app`, `discount-amount`, `sale` | 실제 화면과 컴포넌트 |

- 회색은 무채색 한 줄(#fafafa → #4a4a4a)이다. 웹과 앱이 2차·3차 글자에 서로 다른 회색을 쓴다(웹 #666666·#8a8a8a, 앱 #777777·#888888).
- 같은 값이 여러 역할을 맡는다: #245eff는 웹 쿠폰·앱 장바구니 배지·검색 1~3위, #0078ff는 앱 결제 버튼·하락 삼각형, #ff0000은 앱 할인율·상승 삼각형·불가 안내.

### 역할별 색
- **앱 파랑(`primary-app` #0078ff)**: 결제하기·구매하기 채움, 장바구니 담기 테두리·글자, 체크박스·라디오·결제수단 선택, 말풍선. 눌림·비활성 짝은 확인 필요.
- **검정(`ink` #000000)**: 제목·가격·선택 탭 글자, 주문 완료 화면의 "다음"·"사용" 버튼. 선택 탭 밑줄 2pt.
- **할인 두 색**: 할인율은 빨강(웹 `sale` #f31110, 앱 `save-red` #ff0000), 할인 금액은 `discount-amount` #14aaff 마이너스 숫자. 둘은 항상 짝으로 나온다.
- **쿠폰 파랑(`coupon` #245eff)**: 글자 + `coupon-border` #d5e0ff 테두리. 앱 "쿠폰받기"만 `coupon-download` #4162c9 채움.

- 앱 파랑 #0078ff는 구매 흐름의 행동(결제하기·구매하기·장바구니 담기)과 선택 표시(체크박스·라디오·결제수단)에만 쓴다.
- 할인율은 빨강(웹 #f31110, 앱 #ff0000 "n% SAVE"), 할인 금액은 하늘색 #14aaff 숫자로 나눠 쓴다.
- 쿠폰·혜택 안내는 #245eff 글자에 #d5e0ff 테두리를 쓴다. 앱 "쿠폰받기" 버튼만 #4162c9 바탕이다.

- #9ea2a7·#e85130은 행사 그림 색이라 평소 UI에 쓰지 않는다.

### Don't
- 파랑 #0078ff를 제목·장식에 쓰지 않는다. 구매 흐름 행동과 선택 표시에만.
- 할인율과 할인 금액을 같은 색으로 쓰지 않는다(빨강 % / 하늘색 -금액).
- 하늘색 #14aaff, 별점 #fa9200을 흰 바탕 본문 글자로 쓰지 않는다(대비 2.6:1, 2.3:1).
- 행사 그림 색 #9ea2a7·#e85130을 버튼·바탕 같은 UI 색으로 쓰지 않는다.
- 웹 회색(#666666)과 앱 회색(#777777)을 한 화면에 섞지 않는다.

## 3. 타이포그래피
- 글꼴: Pretendard(웹 실측. `"Pretendard Variable", Pretendard, sans-serif`). 앱 글꼴은 1배율 캡처로 구분하지 못해 확인 필요.
- 대체 글꼴: sans-serif
- 자간: 웹 normal(0). 웹 줄 간격은 크기보다 4~6px 큰 고정 값이다(예: 13px → 18px).

- 앱 구매 흐름은 웹보다 한 단계 크게 쓴다. 본문 14pt, 구획 제목 18pt 굵게.

- 앱 상품명은 13pt 굵게, 두 줄에서 말줄임한다.
- 9pt 이하 글자는 배지·"AD" 같은 표시에만 쓴다.
- 웹은 행간을 크기보다 4~6px 큰 고정 값으로 둔다(13px → 18px, 14px → 20px).
- 굵기는 400·500·600·700 네 가지. 웹 숫자(가격·할인율)는 600, 앱 숫자는 700. (관찰에서 정리)

### Don't
- 웹 본문을 13px보다 키워 14pt 앱 크기로 맞추지 않는다. 웹과 앱의 단계는 따로다.
- 9px 이하 글자를 문장에 쓰지 않는다. "쿠폰"·"AD"·"EVENT" 같은 짧은 표시만.
- 상품명을 두 줄 넘게 늘이지 않는다. 앱 상품명은 13pt 굵게 두 줄에서 말줄임.
- 가격을 보통 굵기(400)로 쓰지 않는다.

## 4. 레이아웃·간격
- 기준 화면: 앱 375×812pt 아이폰. 상태 표시줄 44pt, 상단 바 약 56pt. 검색 시작 화면 1장은 430pt 폭 기기 캡처다. 웹은 데스크톱 1362px 창.
- 화면 좌우 여백: 앱 글자·입력창·구획 제목 14pt, 하단 파랑 버튼 12pt. 앱 홈 15pt, 앱 검색 화면 18pt. 웹 상단 바 좌우 16px, 메인 탭 바 좌우 8px + 탭마다 좌우 7px.
- 기본 단위: 4로 보인다. 공식 단위는 확인 필요.
- 간격 단계(관찰, pt): 3, 4, 5, 8, 10, 12, 14, 15, 16, 18, 20, 30, 40
- 웹에서 실측한 패딩 값: 2, 4, 5, 6, 7, 8, 12, 14, 16px
- 그리드·최대 폭: 웹 홈 상품 카드 폭 246px(1362px 창 기준). 카드 사이 간격은 확인 필요. 앱 결제수단 버튼은 3열 그리드, 버튼 108×48pt, 가로·세로 사이 10pt.

### 앱 화면 구조

- 앱 하단 탭 바: 흰 바탕, 위 1pt #f1f1f1 선, 홈 인디케이터 포함 약 87pt. 아이콘 약 20pt + 이름 11pt.

### Don't
- 앱 구획을 카드 그림자로 나누지 않는다. 10pt #f1f1f1 띠를 쓴다.

- 가로 스크롤 목록의 마지막 보이는 항목을 화면 안에 딱 맞추지 않는다. 다음 항목이 걸쳐 보여야 넘길 수 있다는 것이 드러난다.
- 관찰한 간격(3·4·5·8·10·12·14·15·16·18·20·30·40) 밖의 값을 새로 만들지 않는다.

## 5. 모서리·고도·모션
1pt = CSS 1px로 본다. 앱 값은 1배율 캡처에서 모서리 번짐 길이를 보고 반올림했다.

| 토큰 | 값 | 쓰임 |
|---|---|---|
| radius-none | 0px | 상품 사진(웹·앱), 웹 상세 탭 버튼·띠 배너, 앱 입력창·선택창, 앱 주문 완료 화면 버튼("주문 상세보기", "다음"), 앱 시트 위쪽 |
| radius-xs | 2px | 웹 랭킹 숫자·통계 배지(높이 16px), 앱 "사용"·"쿠폰받기" 작은 버튼, 앱 "EVENT" 배지 |
| radius-sm | 4px | 웹 버튼·칩·배너 카드·입력 기본값, 앱 파랑 결제하기·장바구니 담기 버튼, 결제수단 버튼, 주문 상세 외곽선 버튼, 말풍선 안내, 앱 홈 검색창·바로가기 칩·배너 아래 모서리, 앱 검색창·최근 검색어 칩 |
| radius-pill | 100px | 웹 쿠폰·발매 알약 배지(26×18px), 앱 배송지 이름 알약(높이 28pt) |
| radius-full | 9999px | 웹 56×56px 원형 바로가기·4px 알림 점, 앱 체크박스·라디오(지름 약 20pt), 앱 홈 떠 있는 성별 전환 원·장바구니 숫자 배지 |

- 테두리
  - border: 1px solid #e0e0e0 — 웹 아웃라인 버튼, 구분선. 앱 옵션/수량 버튼
  - border-strong: 1px solid #000000 — 웹 강조 아웃라인 버튼(후기 전체보기 등)
  - border-chip: 1px solid #cccccc — 웹 카테고리 칩. 앱 입력창·결제수단 버튼(추정)
  - border-selected: 1px solid #0078ff — 앱 선택된 결제수단 버튼, 장바구니 담기 버튼
  - border-coupon: 1px solid #d5e0ff — 웹 쿠폰 알약 배지

### 고도
- 앱 약관 시트·옵션 시트·하단 고정 버튼 영역 위로 약 15pt 번지는 옅은 회색 그림자만 있다. 웹은 그림자 없음.
- 층은 면 색으로 나눈다: 앱 홈은 #1a1b1f 상단 → #f5f5f5 본문 → 흰 칩·카드. 주문 화면은 흰 구획 + #f1f1f1 띠.
- 바텀시트는 뒤를 어둡게 덮지 않는다(딤 없음).

### 모션
- 확인 필요(캡처와 computed style로는 길이·이징을 알 수 없다).

### Don't
- 상품 사진에 모서리를 주지 않는다. 0px.
- 8px보다 큰 모서리를 버튼·카드에 쓰지 않는다. 원형은 체크·라디오·알약 배지·알림 점·원형 바로가기만.
- 카드·버튼에 그림자를 넣지 않는다.
- 시트를 띄울 때 배경 딤을 깔지 않는다.

- 규칙: 결제수단처럼 하나만 고르면 3열 상자, 약관처럼 여러 개면 원형 체크. 선택은 파랑 하나로 표시한다. (관찰에서 정리)

## 7. 패턴
- 목록 → 상세: 웹 카드(사진 5:6 → 브랜드 → 상품명 → 할인율·가격 → 좋아요·별점 → 쿠폰 배지)에서 상세로 간다. 상세는 4칸 탭(정보·추천·후기·문의)과 44px 접기 목록으로 정보를 나눈다.
- 구매 흐름: 상품 화면 구매하기 → 옵션 시트(장바구니 담기 + 구매하기) → 장바구니(택배배송/매장 픽업 탭, "총 [n]개 | [금액] 결제하기") → 주문서(배송지·결제수단·최종 결제금액 구획, 약관 동의 시트) → 주문 완료(검정 "다음" + 외곽선 "주문 상세보기"). 하단 고정 파랑 버튼 하나가 끝까지 이어진다.
- 금액 요약: 왼쪽 이름·오른쪽 값 줄을 쌓고, 할인은 빨강 % + 하늘색 마이너스 금액, 합계는 20pt 굵게. 구획 제목 오른쪽 꺾쇠로 접는다.
- 검색: 홈 검색창(행사 문구 안내) → 검색 시작 화면(최근 검색어 칩, 인기·급상승 순위 2열, 기준 시각 표시). 검색 결과 화면은 보지 않아 확인 필요.
- 바텀시트: 배경을 어둡게 덮지 않고 위 그림자만 두며, 꺾쇠로 닫는다.
- 빈 상태·오류: 확인 필요(웹·앱 모두 해당 화면을 보지 않았다). 만든다면 9장 말투(짧은 명사 버튼, 해요체 안내)를 따른다.
- 폼·결제: 결제수단은 3열 상자에서 하나를 고른다(선택은 파랑 테두리). 약관은 "전체 동의하기" 아래 항목별 "[필수]" + "자세히" 링크.

## 9. 글쓰기 톤
- 말투: 메뉴와 버튼은 2~4글자 명사(랭킹, 세일, 장바구니, 사용, 다음). 문장 대신 숫자를 앞에 둔다. 안내 문장은 해요체·합니다체를 섞는다. 완료 문장은 "~되었습니다.", 권유 말풍선은 "~하세요!".
- 버튼 문구 꼴: 금액이 먼저다. "[금액] 결제하기", "지금 구매하면 [금액] 할인", "[n]% SAVE".
- 숫자·단위 표기: 할인 숫자에는 마이너스 기호를 붙인다. 숫자가 크면 "1.3천", "1.4만"처럼 줄인다. 웹 배지는 "[숫자]명이 구매 중", "판매 [숫자]개"처럼 사회적 증거를 숫자로 보여 준다.
- 영문 짧은 표시를 섞는다(SAVE, EVENT).
- 검색 화면 순위에는 기준을 붙인다("날짜 시각, 성별 기준"). 검색창 안내 글자는 해요체 요청형, 홈 검색창에는 행사 문구를 넣는다.

## 10. Do & Don't
관찰 기반 문서의 규칙은 "이 서비스 화면에서 반복되는 규칙"을 SylviaLab이 정리한 것이다(공식 규칙 아님).

### Do
- 상품 사진은 모서리 0px으로 꽉 채운다(웹 카드 246×295px, 앱 썸네일 66×80pt).
- 앱 구매 흐름 주요 버튼은 화면 폭·높이 48pt·#0078ff·모서리 4pt 하나로 둔다.

### Don't
- 카드나 버튼에 그림자를 넣지 않는다. 그림자는 바텀시트와 하단 고정 버튼 영역 위쪽에만 쓴다.

- 행사 그림 색(#9ea2a7, #e85130)을 평소 UI 색으로 쓰지 않는다.
- 파랑 #0078ff를 장식이나 제목 글자에 쓰지 않는다(행동·선택·말풍선에만).
- 하늘색 #14aaff를 흰 바탕 본문 글자로 넓게 쓰지 않는다(대비 2.6:1).
