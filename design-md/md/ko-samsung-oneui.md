# 삼성 One UI 디자인 시스템

> 근거: 공개 문서 기반 (Samsung Developers One UI 디자인 가이드, Samsung Design System 페이지)
> 작성: SylviaLab · 최종 수정 2026-10-31

이 문서는 디자인 시스템의 다섯 층(원칙, 토큰, 컴포넌트, 사용 규칙, 구현·검증)을 한 파일로 줄인 요약이다. 맨 위 YAML은 도구와 AI가 그대로 읽는 값이고, 아래 글은 그 값을 언제·왜 쓰는지 설명한다. 문서의 dp 값은 YAML에 1dp = 1px로 옮겼다.

## 1. 개요와 원칙
- 서비스 성격: 갤럭시 휴대폰·태블릿·폴더블·워치·DeX에 들어가는 삼성 안드로이드 사용자 경험. 앱 하나가 아니라 기기 전체의 화면 규칙이다.
- 디자인 인상 한 줄: 화면 위쪽은 보는 곳, 아래쪽은 누르는 곳. 차분한 단색 면 위에 파랑 하나로 조작 요소를 표시하고, 버튼과 아이콘은 둥글게 굴린다.
- 공식 시스템 이름: One UI (글꼴은 SamsungOne, 상위 체계는 Samsung Design System)
- 디자인 원칙 4개(공식 문서 요약, 출처: https://developer.samsung.com/one-ui/overview.html):
  1. 지금 하는 일에 집중하게 한다. 경로를 짧게.
  2. 자연스럽게 조작한다. 손이 닿는 아래쪽에 조작 요소를 둔다.
  3. 눈이 편하게 한다. 다크 모드, 고대비 키보드, 글자 크기 조절.
  4. 기기와 화면 크기에 맞춰 반응한다.
- 톤: 차분한 면, 한 손 조작, 파랑은 조작 요소에만.
- 공개 문서는 원칙과 행동 규칙 위주다. 픽셀 수치는 대부분 그림 안에만 있어서 이 문서에는 `확인 필요`가 많다.

### 특장점
- 화면을 보는 영역과 누르는 영역으로 나눈다 — 위는 확장 앱 바의 큰 제목(viewing area), 아래는 버튼(interaction area)이고, 선택·확인 대화상자도 화면 아래쪽에 띄워 큰 화면에서도 손이 닿게 한다.
- 깊이 표현 규칙이 구체적이다 — 앞 화면과 관련 없으면 블러 + 딤, 밀접하면 그림자만. 블러는 혼자 쓰지 않고, 딤과 그림자를 동시에 쓰지 않는다.
- 모션 수치와 곡선을 정해 둔다 — 길이 100~500ms, 기본 곡선 One UI Basic PathInterpolator(0.22, 0.25, 0.00, 1.00), Linear는 투명도 변화에만.
- 기기 폭에 맞춘 분기점이 있다 — Compact 600dp 미만, Medium 600~840dp, Expanded 840dp 이상. 폭 600dp 이상이면 큰 화면 레이아웃으로 바꾸고, 휴대폰·태블릿·폴더블·DeX·분할 보기를 모두 대상에 넣는다.
- 접근성을 수치로 못 박는다 — 작은 글자 4.5:1, 큰 글자 3:1(보통 18dp 초과, 굵게 14dp 초과), 모든 글자 200% 확대에도 깨지지 않기, 목록 주 텍스트 31자 이내.

### 배울 점
- 큰 화면에서 버튼을 배치할 때 One UI처럼 위는 정보, 아래는 조작으로 나누고 확인 대화상자를 아래쪽에 띄운다.
- 새 화면을 겹쳐 띄울 때 One UI처럼 앞 화면과의 관계로 표현을 고른다(관련 없음: 블러 + 딤, 밀접함: 그림자만).
- 다크 모드를 만들 때 One UI처럼 토글·체크박스 같은 기능 컴포넌트 색(#3e91ff)은 라이트·다크에서 같게 두고, 글자·버튼 파랑만 모드마다 밝기를 조정한다(#0072de → #3e91ff).

### 이 문서를 읽는 AI 에이전트에게
- 색은 YAML 역할 이름(`primary-dark`, `primary`, `control-activated`)으로 쓴다. 공개된 HEX는 파랑 3개뿐이니 바탕·글자·상태 회색 HEX를 지어내지 말고 플랫폼(안드로이드) 기본 테마 값을 쓴다고 표시한다.
- 파랑은 조작 요소(채움 버튼, FAB, 슬라이더, 토글, 체크박스)에만 쓴다. 넓은 면과 전체 화면 배경에는 쓰지 않는다.
- 배치는 "위는 보는 곳, 아래는 누르는 곳"이 먼저다. 확인 대화상자·주요 버튼은 화면 아래쪽에 둔다.
- 개수 규칙(앱 바 동작 3개, 하단 탭 5개, 목록 31자, 토스트 3줄)을 숫자 그대로 지킨다.
- 판단이 어려우면 더 차분한 면, 더 적은 층(딤과 그림자 중 하나만), 더 짧은 문장을 고른다.

## 2. 색상
### 색 체계
One UI 문서는 **시스템 기본색(파랑) + 앱 색 + 차분한 면** 세 갈래로 색을 설명한다. 공개 HEX는 파랑 세 단계뿐이다.

| 층 | 예시 | 쓰는 곳 |
|---|---|---|
| 시스템 기본색 | #0072de, #0381fe, #3e91ff | 조작 요소. 모드마다 밝기 조정 |
| 앱 색 | 앱 아이콘 색(예: 전화 앱 초록) | 그 앱의 통화 버튼, 선택된 탭, 스크롤 막대 |
| 면 | 바탕, 포커스 블록 3유형 | 차분한 단색. HEX는 문서 그림에만 있음 |

### 브랜드·행동
| 토큰 | HEX | 쓰임 |
|---|---|---|
| primary dark | #0072de | 라이트: 채움 버튼 바탕, 보조 글자(sub text) |
| primary | #0381fe | 플로팅 액션 버튼, 슬라이더(라이트·다크 같음) |
| color control activated | #3e91ff | 체크박스, 켜짐/꺼짐 토글의 켜진 상태(라이트·다크 같음) |

- 파랑이 시스템 기본색이다. 주요 컴포넌트에 쓰고, 모드마다 읽기 좋게 밝기를 조정한다.
- 각 앱은 앱 아이콘 색을 앱 안으로 가져와 쓴다. 예: 전화 앱은 초록을 통화 버튼, 선택된 탭, 스크롤 막대에 쓴다.

### 바탕·선
| 토큰 | HEX | 쓰임 |
|---|---|---|
| 라이트 바탕 | 확인 필요 | 화면 바탕 |
| 라이트 포커스 블록 | 확인 필요 | 목록·카드 묶음 면 |
| 다크 바탕 | 확인 필요 | 다크 모드 바탕·메뉴(문서상 검정 또는 짙은 회색) |

- 공개 문서에는 바탕·글자 회색의 HEX가 없다. 테마 예시는 그림으로만 나온다.

### 글자
| 토큰 | HEX | 쓰임 |
|---|---|---|
| 본문 글자 | 확인 필요 | 본문 |
| 보조 글자 | 확인 필요 | 설명 |

### 상태
| 토큰 | HEX | 쓰임 |
|---|---|---|
| success | 확인 필요 | |
| warning | 확인 필요 | |
| error | 확인 필요 | |
| info | 확인 필요 | |

### 다크 모드
| 토큰 | HEX | 쓰임 |
|---|---|---|
| primary dark | #3e91ff | 다크: 채움 버튼 바탕, 보조 글자 |
| primary | #0381fe | 다크: 플로팅 액션 버튼, 슬라이더 |
| color control activated | #3e91ff | 다크: 체크박스, 토글 켜짐 |

- 다크 모드는 바탕·메뉴를 검정이나 짙은 회색으로 바꿔 눈부심을 줄인다.

### 역할별 색
- **#0072de(`primary-dark`)**: 라이트 채움 버튼(높은 강조) 바탕, 보조 글자. 다크에서는 #3e91ff로 바뀐다. 눌림은 물결(ripple), 비활성 색은 확인 필요.
- **#0381fe(`primary`)**: FAB, 슬라이더. 라이트·다크 같다.
- **#3e91ff(`control-activated`)**: 체크박스·토글 켜짐. 라이트·다크 같다. 흰 바탕 글자로는 쓰지 않는다(3.1:1).
- **회색 채움**: 중간 강조 버튼 바탕. HEX는 확인 필요.
- **앱 색**: 앱 아이콘 색을 그 앱의 핵심 조작 요소에 가져온다.

### 화면 모드
- 라이트·다크 두 테마가 있다. 다크는 바탕·메뉴를 검정 또는 짙은 회색으로 바꾼다.
- 기능 컴포넌트(토글·체크박스) 색은 두 모드에서 같고, 버튼·글자 파랑만 밝기를 조정한다.
- 고대비 키보드와 글자 크기 조절이 원칙("눈이 편하게")에 들어 있다. 고대비 테마의 색 값은 확인 필요.
- 다크 모드에서 전체 화면 사진이 튀지 않는지 확인한다.

### 색 사용 규칙
- 파랑은 조작 요소(채움 버튼, FAB, 슬라이더, 토글, 체크박스)에 쓴다.
- 기능 컴포넌트(토글·체크박스 등)는 라이트와 다크에서 같은 색을 유지한다.
- 바탕과 포커스 블록은 차분한 단색으로 둔다. 바탕과 블록의 대비는 낮게, 글자와 바탕의 대비는 높게.
- 넓은 면에는 차분한 색, 작은 면에는 밝은 색.
- 그라데이션은 시선을 이끌 때만 쓴다. 복잡해지면 뺀다.
- 전체 화면 배경에는 따뜻한 그라데이션을 쓰고, 차가운 파랑 단색 전체 화면은 피한다.
- 포커스 블록 세 가지
  - 유형 1: 표준 단색. 메시지 목록처럼 가장 흔한 형태.
  - 유형 2: 앱 색을 옅게 깐 면. 켜짐/꺼짐 토글 영역 등. 모드마다 조정.
  - 유형 3: 그라데이션. 조심해서 쓴다.
- 앱 아이콘: 밝고 선명한 단색 바탕 + 흰 심볼. 그라데이션은 인접색 3개 이하.

### Don't
- 파랑을 넓은 면이나 전체 화면 배경에 쓰지 않는다. 전체 화면은 따뜻한 그라데이션, 파랑은 조작 요소에만.
- 다크용 #3e91ff를 흰 바탕 글자로 쓰지 않는다(3.1:1).
- 토글·체크박스 색을 다크 모드에서 바꾸지 않는다.
- 바탕과 포커스 블록의 대비를 세게 두지 않는다. 대비는 글자와 바탕 사이에 둔다.
- 앱 아이콘 그라데이션에 인접색 4개 이상을 섞지 않는다.

## 3. 타이포그래피
- 글꼴: SamsungOne(삼성 전용 서체. 26개 문자 체계, 400개 넘는 언어, 25,000자 이상 글리프. 외부 배포 라이선스 확인 필요)
- 한글 서체 이름: 확인 필요
- 대체 글꼴: 확인 필요 (안드로이드 기본 산스 사용이 일반적이나 공식 문서 명시는 찾지 못했다)
- 서체 성격: 손글씨 느낌이 살짝 남은 휴머니스트 산스. 크기와 언어가 달라도 같은 인상을 주도록 설계했다.

### 위계와 사용처
공개 문서에 sp 단위 표가 없어 자리만 둔다. 크기를 지어내지 않는다.

| 단계 | 크기(pt) | 굵기 | 행간 | 쓰임 |
|---|---|---|---|---|
| 앱 바 큰 제목 | 확인 필요 | 확인 필요 | 확인 필요 | 확장된 앱 바 가운데 제목 |
| 목록 주 텍스트 | 확인 필요 | 확인 필요 | 확인 필요 | 목록 한 줄 이름 (31자 이내) |
| 목록 보조 텍스트 | 확인 필요 | 확인 필요 | 확인 필요 | 설정 설명 |

- 공개 문서에서 sp 단위 글자 크기 표를 찾지 못했다.
- 큰 글자 기준: 보통 굵기 18dp 초과, 굵은 글자 14dp 초과(대비 3:1 적용 기준).

### 규칙
- 자막과 이미지 속 글자를 빼고 모든 글자가 200%까지 커져도 깨지지 않아야 한다.
- 목록 주 텍스트는 명사나 짧은 동사구로, 31자 이내로 써서 두 줄로 넘어가지 않게 한다.
- 긴 앱 바 제목은 자동으로 줄어들고, 그래도 넘치면 말줄임표를 쓴다.
- 토스트는 한 줄 정도, 어떤 언어에서도 3줄을 넘기지 않는다.
- 같은 서체로 26개 문자 체계를 쓰므로, 다국어 화면에서도 글꼴을 섞지 않는다. (SylviaLab 정리)

### Don't
- 글자 크기를 고정해 200% 확대를 막지 않는다.
- 목록 주 텍스트를 31자 넘게 써서 두 줄로 넘기지 않는다.
- 긴 앱 바 제목을 잘라 내지 않는다. 먼저 자동으로 줄이고, 그래도 넘치면 말줄임표.
- 큰 글자 기준(보통 18dp 초과, 굵게 14dp 초과)에 못 미치는 글자에 3:1 대비를 적용하지 않는다. 4.5:1이 필요하다.

## 4. 레이아웃·간격
- 기준 화면: 모바일(Compact, 폭 600dp 미만). 큰 화면은 아래 분기점 표.
- 화면 좌우 여백: 정보와 조작 요소는 좌우 최소 24dp 안쪽에 둔다(모바일). 데스크톱(DeX) 값은 확인 필요.
- 기본 단위: 확인 필요
- 간격 단계(pt): 확인 필요(공개 문서에서 숫자로 확인한 간격은 좌우 24dp뿐)
- 그리드·최대 폭: 목록 그리드, 카드 그리드, 2열 그리드, 3열 그리드. 각 열·거터 수치는 확인 필요.
- 화면 구조: 위는 보는 영역(viewing area), 아래는 조작 영역(interaction area). 큰 화면에서도 버튼이 손에 닿게 한다.

### 큰 화면·폴더블 분기점
| 창 크기 | 폭(dp) | 레이아웃 |
|---|---|---|
| Compact | 600 미만 | 휴대폰 레이아웃 |
| Medium | 600 이상 840 미만 | 큰 화면 레이아웃 |
| Expanded | 840 이상 | 큰 화면 레이아웃 |

- 지원 대상: 휴대폰, 태블릿, 폴더블, DeX 외부 모니터, 한 화면 분할 보기.

### 화면 세로 구조
| 구간 | 내용 | 값 |
|---|---|---|
| 위 | 보는 영역: 확장 앱 바 큰 제목 + 부가 정보 | 높이 확인 필요 |
| 가운데 | 목록·카드(포커스 블록) | 블록 사이 여백 확인 필요 |
| 아래 | 누르는 영역: 하단 바, 대화상자, 주요 버튼 | 높이 확인 필요 |
| 좌우 | 정보·조작 요소 안쪽 여백 | 최소 24dp |

### 간격 적용 규칙
- 폭 600dp 이상이면 큰 화면 레이아웃을 쓴다.
- 여백은 포커스 블록 유형(3가지)마다 다르게 최적화한다. 수치는 확인 필요.
- 카드 안 본문이 3줄을 넘으면 글자만 있는 카드를 쓴다.
- 조작 요소는 화면 아래쪽에, 정보는 위쪽에 둔다.

### Don't
- 정보·조작 요소를 좌우 24dp 밖(화면 끝 쪽)에 두지 않는다.
- 폭 600dp 이상에서 휴대폰 레이아웃을 늘려 쓰지 않는다.
- 주요 버튼을 화면 위쪽에 두지 않는다. 큰 화면에서 손이 닿지 않는다.
- 3줄 넘는 본문을 이미지 카드에 넣지 않는다. 글자만 있는 카드로 바꾼다.

## 5. 모서리·고도·모션
| 토큰 | 값 | 쓰임 |
|---|---|---|
| 버튼 모서리 | 18px | 채움 버튼 배경·물결(ripple) 마스크(문서 값 18dp) |
| 앱 아이콘 | 확인 필요 | 둥근 정사각형 바탕, 수치 확인 필요 |
| 카드·포커스 블록 모서리 | 확인 필요 | |


### 고도
  - 그림자: 부드럽고 옅게. 수치 확인 필요. 앞 화면과 관련된 새 화면을 띄울 때.
  - 블러 + 딤: 수치 확인 필요. 앞 화면과 관련 없는 새 화면을 띄울 때.
  - 블러는 혼자 쓰지 않는다. 라이트 테마는 밝은 딤, 다크 테마는 어두운 딤과 짝을 짓는다.
  - 딤과 그림자를 동시에 쓰지 않는다.
  - 그림자는 입체감을 과하게 만들지 않는다. 바탕과 대비가 세면 콘텐츠에서 시선을 뺏는다.
  - 한 화면에 여러 층을 동시에 드러내지 않는다.

### 모션
  - 길이: 최소 100ms(알아볼 수 있는 최소), 최대 500ms(다음 동작을 막지 않게).
  - 기본 곡선: One UI Basic, PathInterpolator(0.22, 0.25, 0.00, 1.00). 빠르게 출발해 천천히 멈춘다.
  - Linear: 투명도 변화(디졸브)에만. 이동·회전·크기에는 쓰지 않는다.
  - Ease in: 화면 밖으로 나가거나 사라질 때.
  - Ease out: 멈추는 과정을 보여 줄 때. 사라지는 요소에는 쓰지 않는다.
  - Ease in out: 움직임 전체를 보여 줄 때. 거리 대비 시간이 짧으면 피한다.
  - 소리·햅틱 가이드가 따로 있다.

| 곡선 | 쓰는 때 | 쓰지 않는 때 |
|---|---|---|
| One UI Basic (0.22, 0.25, 0.00, 1.00) | 기본. 빠르게 출발해 천천히 멈춤 | — |
| Linear | 투명도 변화(디졸브) | 이동·회전·크기 |
| Ease in | 화면 밖으로 나가거나 사라질 때 | — |
| Ease out | 멈추는 과정을 보여 줄 때 | 사라지는 요소 |
| Ease in out | 움직임 전체를 보여 줄 때 | 거리 대비 시간이 짧을 때 |

### Don't
- 블러를 딤 없이 쓰지 않는다. 딤과 그림자를 함께 쓰지 않는다.
- 한 화면에 여러 층을 동시에 드러내지 않는다.
- 모션을 100ms보다 짧게, 500ms보다 길게 두지 않는다.
- Linear를 이동·회전·크기 변화에 쓰지 않는다.

## 6. 컴포넌트
컴포넌트마다 변형, 상태, 쓰는 때, 쓰지 않는 때를 적는다. 보지 못한 상태는 `확인 필요`.

### 6.1 버튼
**크기**

| 크기 | 높이 | 좌우 여백 | 모서리 | 글자 |
|---|---|---|---|---|
| 기본 | 확인 필요 | 확인 필요 | 18dp | 확인 필요 |

**종류**

| 변형 | 모양 | 쓰는 때 |
|---|---|---|
| 플랫(flat) | 바탕 없음 | 강조가 필요 없는 동작, 툴바, 대화상자 |
| 채움, 중간 강조 | 회색 바탕 | 보조 동작 |
| 채움, 높은 강조 | 색 바탕(라이트 #0072de, 다크 #3e91ff) | 주요 동작 |

- 모서리 18dp. 높이·좌우 여백·글자 크기: 확인 필요.
- 상태: 눌림은 물결(ripple) 효과. 비활성 색·로딩은 확인 필요.
- 쓰지 않는 때: 하단 바에 버튼 하나만 두지 않는다.

**규칙**
- 주요 동작은 높은 강조(색 바탕) 하나, 보조는 중간 강조(회색), 툴바·대화상자는 플랫. (문서 정리)
- 버튼은 화면 아래쪽 누르는 영역에 둔다.
- 높이가 공개되지 않았으니 터치 영역 44pt 이상을 따로 확보한다(구현 권장). 아이콘 버튼에는 라벨 토스트(문서 규칙)와 `contentDescription`(구현 권장).

### 6.2 입력창·검색
- 검색 컴포넌트 문서가 있다. 높이·모서리 수치는 확인 필요.
- 상태: 확인 필요.
- 라벨을 힌트 글자로 대신하지 않고, 오류는 문제와 고치는 법을 함께 쓴다(9장 글쓰기 규칙, 화면 배치는 구현 권장).

### 6.3 탭·토글·체크박스
- 하단 탭(bottom navigation): 4개 미만 권장, 필요하면 최대 5개. 글자만 쓴다. 스와이프로 탭을 넘기지 않는다.
- 토글: 켜고 끄는 설정은 목록 줄 오른쪽에 둔다. 켜짐 #3e91ff.
- 체크박스: 켜짐 #3e91ff.
- 칩·탭 높이 수치: 확인 필요.

| 컴포넌트 | 개수·위치 규칙 | 켜짐 색 |
|---|---|---|
| 하단 탭 | 4개 미만 권장, 최대 5개, 글자만, 스와이프 넘김 금지 | 확인 필요 |
| 토글 | 목록 줄 오른쪽 | #3e91ff |
| 체크박스 | 확인 필요 | #3e91ff |

### 6.4 카드·리스트
- 텍스트 목록이 가장 흔하다. 아이콘·이미지를 붙일 수 있다.
- 주 텍스트는 명사나 짧은 동사구. 31자 이내로 써서 두 줄로 넘어가지 않게 한다.
- 보조 텍스트는 이해하기 어려운 설정에만 단다. 누르면 다른 화면으로 가는 항목이면 설명은 그 화면에 둔다.
- 서브헤더로 비슷한 항목을 묶는다.
- 항목을 길게 누르면 제목 없는 드롭다운 메뉴가 뜬다.
- 카드 안 본문이 3줄을 넘으면 글자만 있는 카드를 쓴다.
- 줄 높이·여백: 확인 필요.
- 포커스 블록 3유형(단색 / 앱 색 옅은 면 / 그라데이션)으로 목록을 묶는다. 그라데이션은 조심해서.

### 6.5 앱 바·하단 바
- 앱 바는 두 상태다. 확장 앱 바: 큰 제목이 가운데, 아래에 부가 정보. 기본 앱 바: 한 줄로 압축.
- 아래로 스크롤하면 압축되고 위로 올리면 다시 펼쳐진다. 앱에 돌아오면 마지막 상태를 유지한다.
- 왼쪽 뒤로 가기, 오른쪽 동작 버튼은 3개 이하, 맨 오른쪽에 더 보기.
- 동적 제목: 읽지 않은 수, 다음 알람 같은 정보를 제목 아래에 보여 줄 수 있다. 제목 아래 동작 버튼은 2개까지.
- 하단 바(bottom bar): 동작 버튼 최대 5개. 더 많으면 자주 쓰는 4개 + 더 보기. 버튼 하나만 두지 않는다. 아이콘과 글자를 함께 쓴다.
- 앱 바·탭 높이 수치: 확인 필요.

| 자리 | 최대 개수 |
|---|---|
| 앱 바 오른쪽 동작 | 3개 + 맨 오른쪽 더 보기 |
| 제목 아래 동작 | 2개 |
| 하단 바 동작 | 5개(넘으면 4개 + 더 보기), 최소 2개 |
| 하단 탭 | 최대 5개(4개 미만 권장) |

### 6.6 대화상자·팝업
- 선택·확인 대화상자는 화면 아래쪽에 띄운다(손이 닿는 위치).
- 진행 상황 같은 정보성 팝업은 가운데에 띄운다.
- 결정이 필요한 대화상자는 사용자가 고르거나, 뒤로 가기를 누르거나, 바깥을 누를 때까지 남는다.
- 쓰는 때: 팝업은 입력, 삭제 확인, 개인정보 공유 동의, 중요한 정보에만 쓴다.
- 모서리·여백: 확인 필요.
- 열리면 포커스를 대화상자로 옮기고 뒤로 가기로 닫히게 한다(뒤로 가기·바깥 누르기는 문서 규칙, 포커스 이동은 구현 권장).

### 6.7 토스트·스낵바·라벨 토스트
- 토스트: 한 줄 정도, 어떤 언어에서도 3줄을 넘기지 않는다. 가벼운 정보에만 쓴다.
- 스낵바: 상태 정보 + 오른쪽에 후속 동작 버튼. 몇 초 뒤 또는 다른 곳을 누르면 사라진다.
- 라벨 토스트(툴팁): 아이콘 버튼을 길게 누르면 작은 말풍선으로 이름을 보여 준다. 모든 아이콘 버튼에 단다.
- 쓰지 않는 때: 위험 경고나 선택이 필요하면 토스트 대신 팝업.
- 표시 시간·위치 수치: 확인 필요. 배지: 확인 필요.

### 6.8 아이콘·이미지
- 앱 아이콘: 둥근 모서리 정사각형 바탕 + 단순하고 꽉 찬 심볼. 다른 아이콘과 시각적 무게·비율을 맞춘다.
- 아이콘 격자·선 굵기·크기: 확인 필요.
- 이미지: 전체 화면을 채우는 사진을 바탕으로 쓸 수 있다. 다크 모드에서 사진이 튀지 않는지 확인한다.

## 7. 패턴
- 목록 → 상세: 누르면 다른 화면으로 가는 항목은 설명을 그 화면에 둔다. 목록에서 길게 누르면 제목 없는 드롭다운 메뉴.
- 스크롤과 앱 바: 확장 앱 바(큰 제목) → 아래로 스크롤하면 한 줄 앱 바로 압축 → 위로 올리면 다시 펼침. 돌아오면 마지막 상태 유지.
- 검색: 검색 컴포넌트 문서가 있으나 흐름 수치는 확인 필요.
- 빈 상태·오류: 빈 화면에는 콘텐츠를 추가하는 버튼을 크게 둔다. 할 일이 없는 화면에는 돌아갈 길을 준다. 오류는 지금 생긴 문제와 고치는 법을 함께 알리고, 시스템이 고칠 수 있으면 알아서 고친다.
- 확인·삭제: 화면 아래쪽 대화상자로 묻는다. 고르거나 뒤로 가기·바깥을 누를 때까지 남는다.
- 겹친 화면: 관련 없는 화면은 블러 + 딤, 이어지는 화면은 그림자만.
- 폼·결제: 확인 필요.

### 빈 상태·오류 문구 꼴
9장 규칙([지금 생긴 일] + [할 수 있는 일], 방어성 경고 빼기, 사용자를 직접 부르기)에 맞춘 예:
```
저장한 사진이 없어요.
[사진 추가]
```
```
인터넷에 연결되지 않았어요. Wi-Fi를 켜거나 모바일 데이터를 확인해 보세요.
[설정 열기]
```
(예시 문구, SylviaLab 작성. 한국어 어미 규칙은 확인 필요)

## 8. 접근성
- 글자 대비(WCAG 2.x, 계산값). 바탕·글자 회색 HEX가 공개되지 않아 흰 바탕과 견준 값만 적는다.

| 글자 | 바탕 | 대비 | 본문 기준 4.5:1 |
|---|---|---|---|
| #0072de | 흰색 | 4.7:1 | 통과 |
| #0381fe | 흰색 | 3.8:1 | 미달(큰 글자 3:1은 통과) |
| #3e91ff | 흰색 | 3.1:1 | 미달(큰 글자 3:1은 통과) |
| 채움 버튼 글자 | #0072de | 확인 필요 | 버튼 글자 색이 공개되지 않음 |

- #3e91ff는 다크 모드용 값이라 흰 바탕 글자로 쓰지 않는다. 다크 바탕(검정 또는 짙은 회색) HEX가 공개되지 않아 다크 대비는 확인 필요.
- 문서 기준: 작은 글자 4.5:1 이상, 큰 글자 3:1 이상. 큰 글자는 보통 굵기 18dp 초과, 굵은 글자 14dp 초과.
- 터치 영역: 버튼·목록 높이 수치가 공개되지 않아 44pt 기준과 비교하지 못했다(확인 필요). 조작 요소는 손이 닿는 아래쪽에 둔다.
- 최소 글자 크기: 확인 필요.
- 포커스·스크린리더·글자 확대: 모든 글자가 200%까지 커져도 깨지지 않아야 한다(자막·이미지 속 글자 제외). 모든 아이콘 버튼에 라벨 토스트(이름 말풍선)를 단다. 고대비 키보드가 있다. 포커스 표시와 스크린리더 규칙은 확인 필요.

### 점검 목록
- [ ] 작은 글자 4.5:1, 큰 글자 3:1을 넘는가 (문서 기준)
- [ ] 글자 200% 확대에서 깨지지 않는가 (문서 기준)
- [ ] 모든 아이콘 버튼에 라벨 토스트가 있는가 (문서 기준)
- [ ] 아이콘 버튼·이미지에 `contentDescription`이 있는가 (구현 권장)
- [ ] 버튼·목록 줄의 터치 영역이 44pt 이상인가 (확인 필요, 구현 권장)
- [ ] 키보드·외부 기기(DeX)에서 포커스 표시가 보이는가 (확인 필요)
- [ ] 다크 모드 대비를 다시 쟀는가 (바탕 HEX 확인 필요)

## 9. 글쓰기 톤
- 말투: 사용자를 직접 부르고, 시스템 속사정이 아니라 사용자가 할 수 있는 일을 말한다. 한국어 어미 규칙은 확인 필요.
- 목소리: 하나의 인격, "힘이 되는 조력자". 주인공은 사용자다. 모든 언어에서 같은 목소리, 상황에 따라 어조만 바꾼다.
- 짧고 쉬운 문장. 어려운 단어와 긴 문장을 피한다.
- 일어날지 모를 일에 대한 방어성 경고를 뺀다. 지금 생긴 문제만 알리고 고치는 법을 함께 쓴다.
- 한 화면에 선택 하나, 할 일 하나.
- 설정 설명은 사용자에게 미치는 영향으로 쓰고, 기술 설정은 장점과 대가를 함께 쓴다.
- 특정 지역·계절·성별을 전제하지 않는다.
- 버튼 문구 꼴: 확인 필요. 구조 예시: [지금 생긴 일] + [할 수 있는 일]. 목록 이름은 [명사] 또는 [짧은 동사구].
- 숫자·단위 표기: 확인 필요.

## 10. Do & Don't
아래 규칙은 Samsung Developers One UI 문서(13장 링크)의 내용을 SylviaLab이 요약한 것이다.

### Do
- 선택·확인 대화상자는 화면 아래쪽에 띄운다.
- 정보와 조작 요소는 좌우 최소 24dp 안쪽에 둔다.
- 폭 600dp 이상에서는 큰 화면 레이아웃으로 바꾼다.
- 모션은 100~500ms, 기본 곡선 PathInterpolator(0.22, 0.25, 0.00, 1.00)을 쓴다.
- 목록 주 텍스트는 31자 이내로 쓴다.
- 모든 아이콘 버튼에 라벨 토스트를 단다.
- 토글·체크박스 켜짐 색(#3e91ff)은 라이트·다크에서 같게 둔다.

### Don't
- 블러를 딤 없이 혼자 쓰지 않는다. 딤과 그림자를 동시에 쓰지 않는다.
- 하단 탭을 5개 넘게 두지 않고, 스와이프로 탭을 넘기지 않는다.
- 앱 바 오른쪽 동작 버튼을 3개 넘게 두지 않는다(맨 오른쪽 더 보기 제외).
- 하단 바에 버튼 하나만 두지 않는다.
- Linear 곡선을 이동·회전·크기 변화에 쓰지 않는다.
- 토스트를 3줄 넘게 쓰거나, 위험 경고·선택이 필요한 일에 쓰지 않는다.
- 전체 화면 배경을 차가운 파랑 단색으로 채우지 않는다.
