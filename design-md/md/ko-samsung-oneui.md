# 삼성 One UI 디자인 시스템

> 근거: 공개 문서 기반 (Samsung Developers One UI 디자인 가이드, Samsung Design System 페이지)
> 작성: SylviaLab · 최종 수정 2026-10-31

## 1. 개요
- 서비스 성격: 갤럭시 휴대폰·태블릿·폴더블·워치·DeX에 들어가는 삼성 안드로이드 사용자 경험. 앱 하나가 아니라 기기 전체의 화면 규칙이다.
- 디자인 인상 한 줄: 화면 위쪽은 보는 곳, 아래쪽은 누르는 곳. 차분한 단색 면 위에 파랑 하나로 조작 요소를 표시하고, 버튼과 아이콘은 둥글게 굴린다.
- 공식 시스템 이름: One UI (글꼴은 SamsungOne, 상위 체계는 Samsung Design System)
- 네 가지 원칙(공식 문서 요약)
  - 지금 하는 일에 집중하게 한다. 경로를 짧게.
  - 자연스럽게 조작한다. 손이 닿는 아래쪽에 조작 요소를 둔다.
  - 눈이 편하게 한다. 다크 모드, 고대비 키보드, 글자 크기 조절.
  - 기기와 화면 크기에 맞춰 반응한다.
- 공개 문서는 원칙과 행동 규칙 위주다. 픽셀 수치는 대부분 그림 안에만 있어서 이 문서에는 `확인 필요`가 많다.

## 2. 색상
### 브랜드
| 토큰 | 라이트 | 다크 | 쓰임 |
|---|---|---|---|
| primary dark | #0072de | #3e91ff | 채움 버튼 바탕, 보조 글자(sub text) |
| primary | #0381fe | #0381fe | 플로팅 액션 버튼, 슬라이더 |
| color control activated | #3e91ff | #3e91ff | 체크박스, 켜짐/꺼짐 토글의 켜진 상태 |

- 파랑이 시스템 기본색이다. 주요 컴포넌트에 쓰고, 모드마다 읽기 좋게 밝기를 조정한다.
- 각 앱은 앱 아이콘 색을 앱 안으로 가져와 쓴다. 예: 전화 앱은 초록을 통화 버튼, 선택된 탭, 스크롤 막대에 쓴다.
- 기능 컴포넌트(토글·체크박스 등)는 라이트와 다크에서 같은 색을 유지한다.

### 중립(회색 단계)
| 토큰 | HEX | 쓰임 |
|---|---|---|
| 라이트 바탕 | 확인 필요 | 화면 바탕 |
| 라이트 포커스 블록 | 확인 필요 | 목록·카드 묶음 면 |
| 다크 바탕 | 확인 필요 (문서상 검정 또는 짙은 회색) | 다크 모드 바탕·메뉴 |
| 본문 글자 | 확인 필요 | 본문 |
| 보조 글자 | 확인 필요 | 설명 |

- 공개 문서에는 바탕·글자 회색의 HEX가 없다. 테마 예시는 그림으로만 나온다.
- 규칙: 바탕과 포커스 블록은 차분한 단색으로 둔다. 바탕과 블록의 대비는 낮게, 글자와 바탕의 대비는 높게.
- 다크 모드는 바탕·메뉴를 검정이나 짙은 회색으로 바꿔 눈부심을 줄인다.

|---|---|---|
| success | 확인 필요 | |
| warning | 확인 필요 | |
| error | 확인 필요 | |
| info | 확인 필요 | |

### 색 쓰는 규칙
- 넓은 면에는 차분한 색, 작은 면에는 밝은 색.
- 그라데이션은 시선을 이끌 때만 쓴다. 복잡해지면 뺀다.
- 전체 화면 배경에는 따뜻한 그라데이션을 쓰고, 차가운 파랑 단색 전체 화면은 피한다.
- 포커스 블록 세 가지
  - 유형 1: 표준 단색. 메시지 목록처럼 가장 흔한 형태.
  - 유형 2: 앱 색을 옅게 깐 면. 켜짐/꺼짐 토글 영역 등. 모드마다 조정.
  - 유형 3: 그라데이션. 조심해서 쓴다.
- 앱 아이콘: 밝고 선명한 단색 바탕 + 흰 심볼. 그라데이션은 인접색 3개 이하.
- 명도 대비: 작은 글자 4.5:1 이상, 큰 글자 3:1 이상. 큰 글자는 보통 굵기 18dp 초과, 굵은 글자 14dp 초과.

## 4. 간격·레이아웃
- 기본 단위: 확인 필요
- 간격 단계: 확인 필요
- 화면 좌우 여백: 정보와 조작 요소는 좌우 최소 24dp 안쪽에 둔다(모바일). 데스크톱(DeX) 값은 확인 필요.
- 화면 구조: 위는 보는 영역(viewing area), 아래는 조작 영역(interaction area). 큰 화면에서도 버튼이 손에 닿게 한다.
- 그리드 종류: 목록 그리드, 카드 그리드, 2열 그리드, 3열 그리드. 각 열·거터 수치는 확인 필요.
- 여백은 포커스 블록 유형(3가지)마다 다르게 최적화한다. 수치는 확인 필요.
- 카드 안 본문이 3줄을 넘으면 글자만 있는 카드를 쓴다.

## 5. 모서리·그림자·테두리
| 토큰 | 값 | 쓰임 |
|---|---|---|
| 버튼 모서리 | 18dp | 채움 버튼 배경·물결(ripple) 마스크 |
| 앱 아이콘 | 둥근 정사각형 바탕 | 수치 확인 필요 |
| 카드·포커스 블록 모서리 | 확인 필요 | |
| 그림자 | 부드럽고 옅게. 수치 확인 필요 | 앞 화면과 관련된 새 화면을 띄울 때 |
| 블러 + 딤 | 수치 확인 필요 | 앞 화면과 관련 없는 새 화면을 띄울 때 |

### 깊이(visual depth) 규칙
- 새 화면이 앞 화면과 관련 없으면: 앞 화면에 블러와 딤을 함께 건다.
- 새 화면이 앞 화면과 밀접하면: 그림자만 준다. 두 화면이 이어져 보이게 하려는 것이다.
- 블러는 혼자 쓰지 않는다. 라이트 테마는 밝은 딤, 다크 테마는 어두운 딤과 짝을 짓는다.
- 딤과 그림자를 동시에 쓰지 않는다.
- 그림자는 입체감을 과하게 만들지 않는다. 바탕과 대비가 세면 콘텐츠에서 시선을 뺏는다.
- 한 화면에 여러 층을 동시에 드러내지 않는다.

## 6. 주요 컴포넌트
### 버튼
| 종류 | 바탕 | 쓰임 |
|---|---|---|
| 플랫(flat) | 없음 | 강조가 필요 없는 동작, 툴바, 대화상자 |
| 채움, 중간 강조 | 회색 | 보조 동작 |
| 채움, 높은 강조 | 색(라이트 #0072de, 다크 #3e91ff) | 주요 동작 |

- 모서리 18dp. 눌림은 물결(ripple) 효과.
- 높이·좌우 여백·글자 크기: 확인 필요.
- 비활성 상태 색: 확인 필요.

### 입력창
- 검색 컴포넌트 문서가 있다. 높이·모서리 수치는 확인 필요.

### 카드·리스트
- 텍스트 목록이 가장 흔하다. 아이콘·이미지를 붙일 수 있다.
- 주 텍스트는 명사나 짧은 동사구. 31자 이내로 써서 두 줄로 넘어가지 않게 한다.
- 보조 텍스트는 이해하기 어려운 설정에만 단다. 누르면 다른 화면으로 가는 항목이면 설명은 그 화면에 둔다.
- 켜고 끄는 설정은 줄 오른쪽에 토글을 둔다.
- 서브헤더로 비슷한 항목을 묶는다.
- 항목을 길게 누르면 제목 없는 드롭다운 메뉴가 뜬다.
- 줄 높이·여백: 확인 필요.

### 상단 바·탭 바
- 앱 바는 두 상태다. 확장 앱 바: 큰 제목이 가운데, 아래에 부가 정보. 기본 앱 바: 한 줄로 압축.
- 아래로 스크롤하면 압축되고 위로 올리면 다시 펼쳐진다. 앱에 돌아오면 마지막 상태를 유지한다.
- 왼쪽 뒤로 가기, 오른쪽 동작 버튼은 3개 이하, 맨 오른쪽에 더 보기.
- 동적 제목: 읽지 않은 수, 다음 알람 같은 정보를 제목 아래에 보여 줄 수 있다. 제목 아래 동작 버튼은 2개까지.
- 긴 제목은 자동으로 줄어들고, 그래도 넘치면 말줄임표를 쓴다.
- 하단 탭(bottom navigation): 4개 미만 권장, 필요하면 최대 5개. 글자만 쓴다. 스와이프로 탭을 넘기지 않는다.
- 하단 바(bottom bar): 동작 버튼 최대 5개. 더 많으면 자주 쓰는 4개 + 더 보기. 버튼 하나만 두지 않는다. 아이콘과 글자를 함께 쓴다.
- 앱 바·탭 높이 수치: 확인 필요.

### 바텀시트·모달
- 선택·확인 대화상자는 화면 아래쪽에 띄운다(손이 닿는 위치).
- 진행 상황 같은 정보성 팝업은 가운데에 띄운다.
- 결정이 필요한 대화상자는 사용자가 고르거나, 뒤로 가기를 누르거나, 바깥을 누를 때까지 남는다.
- 팝업은 입력, 삭제 확인, 개인정보 공유 동의, 중요한 정보에만 쓴다.
- 모서리·여백: 확인 필요.

### 토스트·스낵바
- 토스트: 한 줄 정도, 어떤 언어에서도 3줄을 넘기지 않는다. 가벼운 정보에만 쓴다.
- 스낵바: 상태 정보 + 오른쪽에 후속 동작 버튼. 몇 초 뒤 또는 다른 곳을 누르면 사라진다.
- 라벨 토스트(툴팁): 아이콘 버튼을 길게 누르면 작은 말풍선으로 이름을 보여 준다. 모든 아이콘 버튼에 단다.
- 위험 경고나 선택이 필요하면 토스트 대신 팝업.
- 표시 시간·위치 수치: 확인 필요.

## 7. 아이콘·이미지·모션
- 앱 아이콘: 둥근 모서리 정사각형 바탕 + 단순하고 꽉 찬 심볼. 다른 아이콘과 시각적 무게·비율을 맞춘다.
- 아이콘 격자·선 굵기·크기: 확인 필요.
- 이미지: 전체 화면을 채우는 사진을 바탕으로 쓸 수 있다. 다크 모드에서 사진이 튀지 않는지 확인한다.
- 모션 길이: 최소 100ms(알아볼 수 있는 최소), 최대 500ms(다음 동작을 막지 않게).
- 기본 곡선: One UI Basic, PathInterpolator(0.22, 0.25, 0.00, 1.00). 빠르게 출발해 천천히 멈춘다.
- 그 밖의 곡선
  - Linear: 투명도 변화(디졸브)에만. 이동·회전·크기에는 쓰지 않는다.
  - Ease in: 화면 밖으로 나가거나 사라질 때.
  - Ease out: 멈추는 과정을 보여 줄 때. 사라지는 요소에는 쓰지 않는다.
  - Ease in out: 움직임 전체를 보여 줄 때. 거리 대비 시간이 짧으면 피한다.
- 소리·햅틱 가이드가 따로 있다.

## 8. 글쓰기 톤(UX 라이팅)
- 말투: 사용자를 직접 부르고, 시스템 속사정이 아니라 사용자가 할 수 있는 일을 말한다. 한국어 어미 규칙은 확인 필요.
- 목소리: 하나의 인격, "힘이 되는 조력자". 주인공은 사용자다. 모든 언어에서 같은 목소리, 상황에 따라 어조만 바꾼다.
- 짧고 쉬운 문장. 어려운 단어와 긴 문장을 피한다.
- 일어날지 모를 일에 대한 방어성 경고를 뺀다. 지금 생긴 문제만 알리고 고치는 법을 함께 쓴다. 시스템이 고칠 수 있으면 알아서 고친다.
- 한 화면에 선택 하나, 할 일 하나.
- 빈 화면에는 콘텐츠를 추가하는 버튼을 크게 둔다. 할 일이 없는 화면에는 돌아갈 길을 준다.
- 설정 설명은 사용자에게 미치는 영향으로 쓰고, 기술 설정은 장점과 대가를 함께 쓴다.
- 특정 지역·계절·성별을 전제하지 않는다.
- 구조 예시: [지금 생긴 일] + [할 수 있는 일]. 목록 이름은 [명사] 또는 [짧은 동사구].
